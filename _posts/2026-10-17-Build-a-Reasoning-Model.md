## Understanding reasoning models

> - an LLM generates reasoning autoregressively, which means it predicts one token at a time based on statistical patterns in its training data. As a result, the LLM’s “reasoning steps” are not guaranteed to be logically sound, even if they look convincing.
> - current LLM reasoning is probabilistic, meaning that it generates one token at a time based on statistical patterns in training data, without guarantees of logical consistency.
> - generates responses based on learned text distributions.
> - During pretraining, LLMs are exposed to vast quantities of text and learn to predict the next token by identifying and reproducing statistical associations in that data. This process enables them to generate fluent and coherent text, but it is fundamentally based on learned statistical regularities rather than explicit rules or guaranteed logical inference.

LLM 的输出是逐词元生成的。即使一段回答包含了完整的“推理步骤”，这些步骤也不等于经过形式化验证的证明。模型可以生成看起来连贯、实际上存在错误的解释；模型主要根据训练中学到的文本分布生成下一个词元，因此最终答案和中间过程都可能出错。

## Traditional training stages

> - Pretraining, in which the model learns language patterns from vast amounts of text
> - Instruction fine-tuning, which improves the model’s responses to user prompts
> - Preference tuning, which aligns model outputs with human preferences

传统大模型通常可以分为以下几个训练阶段：

1. **预训练阶段**：模型从大量文本中学习语言模式，目标通常是预测下一个词元。
2. **指令微调阶段**：使用指令和回答示例训练模型，提升模型理解用户提示并按要求作答的能力。
3. **偏好调优阶段**：根据人类偏好或其他偏好信号调整模型，使输出更符合预期的帮助性、准确性和表达方式。

这三个阶段解决的问题不同：预训练提供基础语言能力，指令微调让模型更像一个能够遵循指令的助手，偏好调优则进一步调整输出风格和行为。

## Vocabulary size and sequence length

> A larger vocabulary in a language model increases the model’s size because the embedding and output layers must store more token representations. It can also increase the per-token compute cost of producing next-token probabilities. A larger vocabulary also allows more words to be represented as single tokens rather than being split into subword components, which can reduce sequence length. For example, splitting a word like “Explain” into “Ex” and “plain” results in more input tokens. More tokens lead to longer input sequences, which increases processing time and resource usage. The tradeoff is between a larger vocabulary with a somewhat higher per-token cost and a smaller vocabulary that often produces longer token sequences. For instance, doubling the number of tokens in a sequence can roughly double the computational cost of running the model, since the model has to process and generate more tokens overall.

对应 vocab size 的理解：

- 词表越大，嵌入层和输出层需要保存的词元表示越多，模型参数量可能增加，计算下一个词元概率时的输出成本也可能增加。
- 词表越大，一些词可以被表示为单个词元，而不是拆成多个子词，从而缩短序列长度。
- 词表越小，同一段文本可能需要更多词元表示，输入序列变长后，处理时间和资源消耗也可能增加。
- 因此需要在“更大的词表带来的参数和输出计算成本”和“更小的词表带来的更长序列”之间进行取舍。

## KV caching

> - The key idea is that we can cache certain intermediate values and reuse them at each step of text generation.
> - Previously, each new token generated by the network was concatenated to the entire input sequence and fed back into the model repeatedly. This approach was inefficient because all tokens, except the newly generated one, remained identical in subsequent iterations. By using a KV cache, we avoid redundant computation and instead directly retrieve stored intermediate representations.

KV cache 的核心是缓存 Transformer 各层已经计算出的 key 和 value。在生成新词元时，模型仍然需要计算新词元相关的部分，但不必从头重复计算此前词元的 key 和 value，因此可以减少自回归生成中的重复计算。

这里的“cache”并不是把整个模型的输出直接缓存起来，而是缓存注意力机制会反复使用的中间表示。缓存会占用额外显存或内存，因此上下文越长，KV cache 的容量压力通常也越明显。

## Benchmark-based evaluation

- multiple choice
- verifiers
- leaderboards
- LLM judges

推理能力不能只靠某一个例题判断，通常需要结合不同类型的评测：

- **Multiple choice**：用选择题检查模型能否在给定选项中选出正确答案，评测结果相对容易自动判断。
- **Verifiers**：用规则、程序或其他模型检查答案是否满足要求，尤其适合结果可以验证的任务。
- **Leaderboards**：汇总不同模型在多个基准上的成绩，便于比较，但排行榜本身不是一种具体的推理方法。
- **LLM judges**：让另一个 LLM 对回答进行评分或比较。它可以处理开放式回答，但评分标准和评审模型本身也可能带来偏差。

## Ways to improve reasoning

> Improving reasoning in LLMs can be achieved in a few ways:
>
> - Inference-time compute scaling improves reasoning without retraining (e.g., chain-of-thought prompting).
> - Reinforcement learning involves training models explicitly with reward signals.
> - Supervised fine-tuning and distillation, using examples from stronger reasoning models.

这里可以先区分两类成本：

1. **增加推理时的计算量**：不重新训练模型，而是在生成回答时让模型进行更多思考、采样多个答案或反复修订，例如 chain-of-thought prompting、self-consistency 和 self-refinement。
2. **增加训练阶段的优化过程**：通过强化学习、监督微调或知识蒸馏改变模型本身，使模型在之后的推理过程中表现得更好。

### Three inference-time methods

> - Method 1: Extending the chain-of-thought response to prompt the model to explain its reasoning. This simple technique can substantially improve accuracy.
> - Method 2: Parallel sampling via self-consistency, where the model generates multiple responses and selects the most frequent one.
> - Method 3: Iterative self-refinement, where the model reviews and improves its own reasoning and answers across multiple steps

生成回答时需要消耗更多 token 或执行更多轮计算。

### Chain of Thought

> Note that while the model generated the correct answer in this case, not all problems benefit from chain-of-thought prompting. On simple problems, it can sometimes even degrade the model’s performance, as the model might generate erroneous explanations and mislead itself. This phenomenon is known as “overthinking.”
>
> Chain-of-thought prompting (such as “Explain step by step.”) often yields more accurate answers by encouraging the model to write out its intermediate reasoning, though it increases the number of generated tokens and, in turn, the runtime cost.
>
> chain-of-thought prompting does not provide the model with new knowledge, but it changes how the model uses its existing knowledge.

Chain-of-thought prompting 会要求模型显式写出中间步骤，例如提示它“Explain step by step”。这样做有时可以帮助模型分解复杂问题，但它并不会给模型增加新的知识，同时会增加生成的词元数量和运行成本。

并非所有问题都能从思维链中受益。对于简单问题，额外生成的解释可能引入新的错误，甚至让模型在原本能够回答的问题上“想得过多”。因此，思维链不是对所有任务都有效的通用开关。

## Self-Consistency

> Self-consistency sampling generates multiple answers, extracts the final boxed result from each, and selects the most frequent answer via majority vote to improve answer accuracy.

Self-consistency 的基本做法是：对同一个问题采样多条回答，再比较这些回答的最终结果，选择出现次数最多的结果。它依赖的是多个独立或相对不同的推理路径可能汇聚到同一个答案。

原文用“final boxed result”描述数学题等答案格式比较明确的任务。对于开放式生成任务，答案未必能直接抽取或进行多数投票，因此这种方法并不适合机械地应用到所有问题。

常见的采样控制参数包括：

- **Temperature scaling**：调整采样的随机性。
- **Top-p filter**：从累计概率达到指定阈值的候选词元中采样。
- **Top-k filter**：只在概率最高的若干个候选词元中采样。

这些参数本身不是 self-consistency，而是用来影响多次采样结果的多样性。Self-consistency 的代价是需要生成多份回答；如果所有采样都犯同一种错误，多数投票也无法解决系统性错误。

## Self-Refinement

> Instead of generating and choosing from multiple answers, self-refinement focuses on iteratively refining a single answer to correct potential mistakes.
>
> The self-refinement procedure consists of three stages: generating an initial draft, producing a short critique and fix plan, and generating a revised answer.

Self-refinement 不生成多份答案再投票，而是围绕一份初始答案反复修改。一个基本流程是：

1. 生成初稿；
2. 对初稿进行简短批评，并给出修正计划；
3. 根据批评和计划生成修订稿。

其中的 scorer 可以理解为对答案进行评价的组件：

- **基于规则的方法**：检查答案是否满足格式、数值或程序验证等明确条件。
- **基于 LLM 的方法**：让另一个模型，或同一个模型的另一次调用，对答案进行评价。

Self-refinement 的效果取决于评价是否能够发现真实错误。如果评价本身不可靠，模型可能只是反复改写表达方式，而没有真正修正推理。

## RLHF

- PPO

RLHF（Reinforcement Learning from Human Feedback）通常使用人类偏好数据获得奖励信号，再通过强化学习调整模型，使模型更倾向于产生人类偏好的回答。PPO（Proximal Policy Optimization）是一种可以用于策略优化的强化学习算法。

这里需要区分：人类偏好数据负责提供“什么样的回答更好”的信号，PPO 负责在这个信号下更新模型策略。PPO 并不是 RLHF 的同义词。

## RLVR

- GRPO

RLVR（Reinforcement Learning with Verifiable Rewards）使用可以被验证的奖励信号训练模型，例如答案是否正确、程序是否通过测试或结果是否满足明确规则。与完全依赖主观偏好的奖励相比，可验证奖励更适合数学、代码等有明确结果的任务。

GRPO（Group Relative Policy Optimization）是一种策略优化算法，常与可验证奖励结合用于 RLVR。它通过同一问题上的多个样本进行相对比较来构造训练信号；具体实现和效果还需要结合训练设置与任务类型判断。

## Distillation

知识蒸馏通常使用更强的 teacher model 生成示例，再用这些示例训练较小的 student model。蒸馏的目标不是简单复制模型参数，而是让较小模型学习教师模型的输出模式、解题过程或最终答案。

对于 reasoning model，蒸馏数据可以包含最终答案，也可以包含推理过程。两者的训练效果和成本可能不同，因此需要进一步明确：究竟希望 student 学会更好的最终结果，还是学会产生某种推理轨迹。
